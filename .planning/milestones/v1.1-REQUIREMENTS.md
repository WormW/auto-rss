## Requirements Traceability

### RATE-01: IP-based Rate Limiting

**Status:** ✅ Implemented  
**Phase:** 05  
**Implementation:**
- Token bucket algorithm using golang.org/x/time/rate
- Per-IP isolation via map[string]*entry
- General endpoints: 10 req/s, burst 20
- Auth endpoints: 5 req/min, burst 5

**Files:**
- internal/api/middleware/ratelimit/bucket.go
- internal/api/middleware/ratelimit/store.go

---

**Status:** ✅ Implemented  
**Phase:** 05  
**Implementation:**
- X-RateLimit-Limit: Maximum requests allowed
- X-RateLimit-Remaining: Remaining tokens
- X-RateLimit-Reset: Unix timestamp when limit resets

**Files:**
- internal/api/middleware/ratelimit.go

### RATE-03: 429 Too Many Requests

**Status:** ✅ Implemented  
**Phase:** 05  
**Implementation:**
- HTTP 429 status code when limit exceeded
- Retry-After header with seconds to wait
- Chinese error message: "请求过于频繁，请稍后再试"

**Files:**
- internal/api/middleware/ratelimit.go

### RATE-04: Memory Bounds and Cleanup

**Status:** ✅ Implemented  
**Phase:** 05  
**Implementation:**
- Max entries: 10,000 with LRU eviction
- TTL: 1 hour for inactive clients
- Background cleanup every 5 minutes

### WS-02: Automatic Reconnection

**Status:** ✅ Implemented  
**Phase:** 06  
**Implementation:**
- Exponential backoff: 1s, 2s, 4s, 8s... max 30s
- ±50% jitter to avoid thundering herd
- Max reconnection attempts: unlimited

**Files:**
- webui/src/services/websocket.ts
