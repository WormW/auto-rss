# Plan 07-03: RSS 健康检查 Handler 和路由

## Goal
实现 RSS 订阅健康检查的 API 端点，复用现有的 RSSHealthChecker 服务。

## Files

### Create
- `internal/api/handler/rss_health.go`

### Modify
- `internal/api/router/router.go`

## Implementation Details

### RSSHealthHandler 结构
```go
type RSSHealthHandler struct {
    healthChecker *rss.RSSHealthChecker
    subRepo       repository.SubscriptionRepository
}
```

### 需要实现的方法

1. **CheckAll** - GET /api/v1/rss/health
   - 检查所有订阅的 RSS 健康状态
   - 返回健康检查结果列表
   - 包含统计信息 (healthy/unhealthy/dead count)

2. **CheckOne** - GET /api/v1/rss/health/:subscription_id
   - 检查单个订阅的 RSS 健康状态
   - 返回详细检查结果

3. **GetDead** - GET /api/v1/rss/dead
   - 获取所有失效的 RSS 订阅
   - 返回 dead 状态的订阅列表

4. **TriggerCheck** - POST /api/v1/rss/health-check
   - 触发异步健康检查任务
   - 使用 task manager 启动后台任务
   - 返回任务信息

## Health Status Mapping
- healthy - 可正常访问和解析
- unhealthy - 可访问但解析异常
- dead - 无法访问或返回错误
- unknown - 未检查

## Error Handling
- 400 - 无效的订阅ID
- 404 - 订阅不存在
- 500 - 检查失败

## Success Criteria
- [ ] 健康检查返回正确状态
- [ ] 异步任务正确触发
- [ ] 错误处理完善
- [ ] 返回统一格式
